# 제품 정책

Shallpick은 함께 찍은 사진을 선택하고, 사진에 나온 사람들의 의견을 확인한 뒤 공유를 준비하는 서비스입니다. 이전의 사진 삭제·자동 정리 주제를 현재 목표로 되돌리지 않습니다.

이 문서는 **구현 요구사항**입니다. 현재 시작 화면에 이 기능들이 이미 구현되어 있다는 뜻은 아닙니다.

## 핵심 흐름

앨범 열기 → 내 사진 선택 → 사진 속 인물 확인 → 게시할 곳과 공개 범위 설정 → 확인 요청 → 사진별 응답 → 필요한 수정과 재확인 → 공유 준비

각자가 자신의 게시 후보를 고릅니다. 모든 사람이 하나의 대표 사진을 뽑는 단체 투표로 바꾸지 않습니다.

## 반드시 유지할 규칙

| ID | 규칙 | 구현에서 확인할 것 |
| --- | --- | --- |
| P01 | 공감과 동의는 별개 | 좋아요, 사진 선택, 열람만으로 게시 가능 상태가 되지 않음 |
| P02 | 무응답은 대기 | 시간이 지났다는 이유로 승인하지 않음 |
| P03 | 동의는 요청과 버전에 귀속 | `requestID`, `requesterID`, `contextVersion`, `photoID`, `assetVersion`, `responderID`를 함께 확인 |
| P04 | 사진 수정은 재확인 | 교체한 사진의 기존 동의를 무효화. 다른 사진의 유효한 동의는 유지 |
| P05 | 게시 맥락 변경은 전체 재확인 | 게시할 곳이나 공개 범위를 바꾸면 해당 요청 사진들의 기존 동의를 무효화 |
| P06 | 요청 간 승인 재사용 금지 | 다른 요청·요청자에게 받은 동의를 복사하지 않음 |
| P07 | 사진 제외는 원본 삭제가 아님 | 요청의 후보에서만 빼고 공유 앨범 원본은 보존 |
| P08 | 완료된 사진만 공유 대상 | 해당 사진의 확인 대상 모두가 최신 버전에 동의한 경우만 포함. 일부 완료와 전체 완료 구분 |
| P09 | AI 추천은 확인이 필요 | 사진별 추천 인물을 요청자가 확인·적용한 뒤 전송. 추천을 동의로 취급하지 않음 |
| P10 | 공유 준비와 실제 게시 구분 | 파일 선택·OS 공유창 실행을 SNS 게시 완료로 단정하지 않음 |

요청을 보낼 때 사진 목록, 사진 버전, 확인 대상, 게시 맥락을 스냅샷으로 저장합니다. 이후 앨범에서 사진이 바뀌어도 이미 보낸 요청의 내용을 조용히 덮어쓰지 않습니다. 수정본과 원본을 구분할 수 있게 합니다.

인물 추천을 사용하지 않는 경우에도 확인 대상을 직접 지정하고 확인할 수 있어야 합니다. 다른 사람에게 받은 응답을 요청자가 대신 승인한 것처럼 만들지 않습니다. 프로토타입의 역할 전환은 **시연 모드**로 명시합니다.

## 화면 상태

- 대기, 동의, 수정 요청, 제외, 재확인을 글자와 상태 표시로 구분합니다. 색만으로 의미를 전달하지 않습니다.
- 요청함 배지는 **내 응답이 필요한 요청**을 셉니다. 열람만으로 지우지 않고, 응답 완료 시 사라지며 재확인이 필요하면 다시 표시합니다. 보낸 요청과 취소 요청은 제외합니다.
- 사진이 없거나 요청 대상이 없을 때, 취소했을 때, 뒤로 갔다 돌아왔을 때의 동작을 함께 설계합니다.
- 일부 사진만 완료되면 어떤 사진을 공유할 수 있고 무엇이 대기 중인지 보여줍니다. 대기 중인 사진을 자동으로 포함하지 않습니다.

## 목업의 경계

소셜 로그인, AI 추천, 사진 업로드, 푸시, OS 공유, 서버 동기화는 실제 연결 전까지 목업으로 기록합니다. 핵심 동의·버전 상태 계산은 목업 데이터에서도 실제로 작동해야 합니다. 항상 성공하는 화면 전환만으로 대체하지 않습니다.

예를 들어 “공유가 완료됐어요” 대신 구현된 수준에 맞춰 “공유할 사진을 골랐어요”라고 표현합니다. 시연 모드 안내는 짧게 유지하고, 개발 내부 용어를 모든 화면에 늘어놓지 않습니다.

## 최소 동작 테스트

첫 도메인 구현에서 P01~P10을 사용자 행동 중심으로 검사합니다. 특히 무응답, 사진 교체, 공개 범위 변경, 다른 요청의 승인, 부분 완료, 잘못된 인물 추천 수정, 원본 보존을 포함합니다. 새 조사를 수행하거나 사용자 반응을 관찰하지 않았다면 가설을 조사 결과로 적지 않습니다.
