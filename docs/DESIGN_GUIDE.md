## 화면과 문구

- 화이트 중심의 그레이스케일, 충분한 여백, 사진과 상태가 먼저 보이는 구성을 유지합니다.
- 홈 상단 로고와 고정 하단 탭을 추가하지 않습니다. 로고가 필요하면 시작 화면 등 적절한 위치에 사용합니다.
- “새 앨범”, “사진 추가”는 텍스트 액션이 기본입니다. 앨범 아이콘 대안은 확정안처럼 바꾸지 않습니다.
- 게시할 곳과 공개 범위는 한 줄로 요약하고 시트에서 바꿉니다.
- 사진 아래 겹친 얼굴은 인물 확인으로 연결합니다. 이름은 시트와 접근성 이름에 제공합니다.
- 한 문장에는 하나의 행동을 안내합니다. 중간점 나열과 개발 과정 설명을 줄이고, 상태·대상·다음 행동을 분명하게 씁니다.

## 기본 값

| 역할 | 값 |
| --- | --- |
| 배경 | `#FFFFFF` |
| 주요 글자 | `#242424` |
| 보조 글자 | `#6B6B6B` |
| 보조 표면 | `#F5F5F5` |
| 경계 | `#E5E5E5` |
| 중립 액션 배경 | `#E8E8E8` |
| 주요 제목 | 20 / 28, semibold |
| 화면 제목 | 17 / 24, semibold |
| 본문 | 16 / 24, regular |
| 보조 | 14 / 20, regular |
| 버튼 | 15 / 22, semibold |

기존 디자인 서체는 Pretendard입니다. 앱에 포함할 때 라이선스와 파일 출처를 기록합니다. 아직 폰트를 포함하지 않았다면 시스템 서체를 임시 사용하고 PR에 차이를 적습니다. SwiftUI에서는 포인트와 Dynamic Type을 기준으로 조정합니다. 값을 화면마다 흩어 놓지 않고 공용 디자인 값으로 관리합니다.

터치 영역은 팀 기준 48pt 이상을 목표로 합니다. 작은 화면과 큰 글씨에서 잘림, 버튼 겹침, 시트 스크롤을 확인합니다. 상태는 색과 문구를 함께 사용합니다. 실제 OS가 그리는 상태바·홈 인디케이터를 이미지로 중복 넣지 않고 Safe Area를 따릅니다.

## 디자인 → 구현 → PR

먼저 핵심 흐름과 정상·빈 화면·대기·재확인 상태를 정합니다. 공용 요소를 만든 뒤 실제 데이터 상태를 연결합니다. 디자인 캡처와 실행 캡처는 구분하고, 차이가 있으면 이유를 적습니다. 예쁜 한 화면보다 사용자가 다음 행동을 이해하고 끝까지 실행할 수 있는지를 검토합니다.
