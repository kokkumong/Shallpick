# 사진 상세, 스와이프 안내, 일반 댓글 채팅 연결

기준: `main` 42f76f3. 작업: `feat/photo-detail-comment-guide`.

- 사진 상세의 수달 버튼을 댓글 입력창 옆 하단 오른쪽으로 이동한다. 기존 사진 보기, 저장, 질문 작성은 유지한다.
- 질문 응답 화면에 처음 한 번 약 3초간 위로 싫어, 아래로 좋아 예시를 보여준다. 실제 답변은 저장하지 않는다. 건너뛰기와 사용법 다시 보기, 동작 줄이기를 지원한다.
- 일반 사진 댓글을 사진과 함께 폴더 채팅에 표시한다. 사진에 위치를 지정하는 질문 댓글은 채팅에 공유하지 않는다.
- 댓글을 채팅 메시지로 복제하지 않는다. 동일한 원본 댓글을 조회하므로 삭제와 사진 삭제가 채팅에도 반영된다. 채팅 카드를 누르면 해당 사진과 댓글을 연다.

## 적용 순서

1. Shallpick 프로젝트에 `supabase/migrations/20261119162049_photo_comment_chat_timeline.sql`을 먼저 적용한다.
2. 폴더 구성원 계정으로 `folder_chat_timeline` 조회와 `photo_comments` Realtime 구독을 확인한다.
3. 이 브랜치의 iOS 앱을 배포한다. 기존 버전은 기존 테이블을 그대로 사용할 수 있다.

뷰는 `security_invoker`로 기존 테이블의 접근 정책을 따른다. 새 테이블, 댓글 복사, 질문 댓글 공개, 새 푸시 알림은 추가하지 않는다. 과거 일반 댓글도 원래 작성 시각에 표시된다. 최근 200개 항목 조회는 기존 채팅 제한을 유지한다.

## 검증 구분

- SQL 테스트: 빈 PostgreSQL에서 기존 실제 마이그레이션과 접근 정책을 적용한다. 두 구성원과 외부인, 일반 댓글과 질문 댓글, 삭제, 사진 삭제, 같은 UUID의 메시지/댓글, 읽지 않은 개수를 확인한다.
- iOS 검증: 별도 CI 브랜치에 기존 오프라인 시연 자료를 결합한다. 제품 화면 코드는 동일하며 `SHALLPICK_DEMO` 데이터는 실제 서버 검증을 대신하지 않는다.
- 실제 서버: 현재 연결 계정에는 Shallpick 프로젝트가 없어 적용하지 않았다. 두 실제 계정 간 Realtime 수신은 적용 후 별도 확인해야 한다.

## 실제 계정 최종 확인

1. A와 B가 같은 폴더에 참여하고, C는 참여하지 않는다.
2. A가 일반 사진 댓글을 남긴다. B의 열린 채팅에 사진과 댓글이 한 번 나타나고 C에게는 보이지 않아야 한다.
3. 댓글 카드를 열어 같은 사진과 댓글에 도달하는지 확인한다.
4. A가 댓글을 삭제하면 B 채팅에서도 사라지는지 확인한다. 사진 삭제도 같은 방식으로 확인한다.
5. 질문 화면의 위치 댓글은 질문 안에서만 보이는지 확인한다.
6. 연결 끊김과 복귀, 앱 복귀, 수동 새로고침에서 누락과 중복이 없는지 확인한다.

실제 서버 검증 전에는 완료로 표시하지 않는다. 이 변경은 보류 중인 전원 동의 사진 저장·공유 기능을 포함하지 않는다.
