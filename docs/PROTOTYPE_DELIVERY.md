# 최소 목표: 설치 가능한 프로토타입

**다른 사람이 자신의 iPhone에 설치하고, 사진 선택부터 확인 요청과 응답, 공유 준비까지 직접 실행할 수 있게 배포합니다.** 완성된 서비스나 앱스토어 정식 출시는 첫 목표가 아닙니다.

현재 앱은 시작 화면 단계입니다. 이 문서는 앞으로의 완료 기준이며, 배포나 기기 실행이 완료되었다는 기록이 아닙니다.

## 범위

| 구분 | 이번 최소 목표 P0 | 후속 P1 |
| --- | --- | --- |
| 실행 | SwiftUI iOS 설치형 앱 | 추가 플랫폼은 별도 결정 |
| 로그인 | 명확히 표시한 시연 계정 선택 | 실제 소셜 로그인 |
| 사진 | 허용된 샘플 사진과 로컬 상태 | 기기 사진 업로드와 서버 저장 |
| 인물 | 고정 추천 + 직접 수정·확인 | 실제 인물 인식·매칭 |
| 요청·응답 | 한 기기의 역할 전환으로 전체 흐름 수행 | 서로 다른 휴대폰의 실제 동기화 |
| 동의 정책 | 버전, 재확인, 부분 완료를 실제 상태로 계산 | 서버에서도 동일 규칙 보장 |
| 공유 | 공유 가능한 사진 목록 확인 | 실제 내보내기와 OS 공유 |
| 배포 | 설치 경로, 빌드 번호, 검증된 시연 절차 | 운영·배포 자동화 확대 |

여러 사람이 같은 앱을 설치하는 것과 여러 기기가 데이터를 함께 바꾸는 것은 다릅니다. P0는 로컬 시연을 허용하지만 **실제 공동 사용을 구현했다고 설명하지 않습니다**. 수업의 새 필수 조건이 다중 기기 공동 사용이라면 P1을 제출 범위에 포함하도록 범위를 다시 결정합니다.

## 구현 순서와 완료 조건

| 단계 | 만들 것 | 완료 조건 |
| --- | --- | --- |
| 0. 배포 경로 확인 | Mac/Xcode, 시연 iPhone, 서명 계정, TestFlight 가능 여부 | 기본 앱을 기기에서 열고 설치 경로의 막힘을 먼저 확인 |
| 1. 화면과 상태 연결 | 앨범 → 선택 → 인물 확인 → 게시 설정 → 요청 | 뒤로 가기·선택 수정·빈 상태를 포함해 요청까지 도달 |
| 2. 응답 흐름 | 역할 전환, 사진별 동의·수정·제외 | 무응답은 대기, 일부 완료는 부분 공유로 표시 |
| 3. 수정과 재확인 | 수정본 교체, 게시 맥락 변경 | 변경된 범위만 다시 확인하고 이전 승인을 잘못 사용하지 않음 |
| 4. 배포와 검증 | 설치 가능한 빌드, 안내, 샘플 데이터 초기화 | 작성자 외 1명이 설치하고 핵심 과업을 완료 |

각 단계는 관련 PR로 나눕니다. 첫날부터 설치 경로를 확인하여 마지막에 서명과 배포 문제를 발견하지 않게 합니다. 맡은 사람의 이름은 실제 담당이 결정된 뒤 적고, 최종 반영과 배포 담당은 한 명으로 정합니다.

## 배포 경로

기본 후보는 TestFlight입니다. 서명과 App Store Connect 권한, 빌드 업로드, 테스트 정보, 테스터 접근을 확인합니다. 외부 테스터의 첫 빌드는 검토가 필요할 수 있으므로 제출 직전에 처음 시도하지 않습니다. [Apple TestFlight 안내](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview/)

TestFlight를 사용할 수 없다면 팀이 실제로 사용할 수 있는 서명·기기 설치 경로를 먼저 정합니다. Figma 링크, 시뮬레이터 영상, 저장소 소스만으로는 **앱 배포 완료**라고 표시하지 않습니다. 설치가 막혔으면 “빌드/배포 대기”로 남기고 시연 영상은 보조자료로 제공합니다.

현재 프로젝트의 최소 OS는 iOS 26.0이고 서명 팀은 비어 있습니다. Mac의 Xcode/SDK와 시연 기기를 확인한 뒤 값을 결정합니다. 설치 가능성을 확인하지 않고 최소 버전을 임의로 올리거나 특정 Xcode 버전에서 통과했다고 쓰지 않습니다.

## 시연 확인 과업

1. 샘플 앨범에서 게시할 사진을 고르고 사진 속 인물을 확인한다.
2. 게시할 곳과 공개 범위를 정해 확인을 요청한다.
3. 시연 역할을 바꿔 한 사진에는 동의하고 다른 사진에는 수정을 요청한다.
4. 요청자에게 돌아와 동의가 완료된 사진만 공유 후보에 포함되는지 확인한다.
5. 사진을 바꾸거나 공개 범위를 바꿨을 때 재확인이 필요한지 확인한다.
6. 제외한 사진의 원본이 앨범에 남는지 확인하고 초기 상태로 되돌린다.

사람에게는 버튼 이름을 알려주기보다 목적을 설명합니다. 완료 여부, 망설인 지점, 상태를 오해한 이유를 적고, 큰 문제를 수정한 뒤 다시 확인합니다. 시연 성공을 실제 사용자 연구 결과나 서비스 효과의 통계적 검증으로 설명하지 않습니다.

## 배포 완료 기록

배포 PR 또는 릴리스에 아래 내용을 채웁니다. 실제로 확인하기 전에는 빈 상태를 완료로 바꾸지 않습니다.

| 항목 | 현재 기록 |
| --- | --- |
| 설치 경로와 접근 방법 | 미정 |
| 버전 / 빌드 / 코드 커밋 | 미배포 |
| 지원 OS와 확인 기기 | 프로젝트 설정 iOS 26.0 / 실기기 미확인 |
| 확인한 핵심 흐름 | 미구현 |
| 설치하고 실행한 사람 / 날짜 | 미확인 |
| 목업과 실제 연동 범위 | P0 기준, 실제 구현 시 갱신 |
| 알려진 문제와 재시연 방법 | 구현 후 기록 |

설치 경로·빌드·목업 범위를 PR에 함께 남기고, 배포한 버전과 최신 소스를 혼동하지 않게 합니다. 다음 수정이 생기면 재확인이 필요한 과업과 화면을 갱신합니다.
